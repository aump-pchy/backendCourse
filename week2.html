Week 2

Building Smarter APIs

API จาก Week 1 ตอบข้อมูลได้แบบเดียว สัปดาห์นี้เราทำให้มันกรองตามประเภท ค้นหาด้วย ID รับอุปกรณ์ใหม่ และบอก Client ได้ชัดว่าสำเร็จหรือผิดพลาดตรงไหน

ทำงานนี้แล้วจะได้อะไร

  • เลือก Status Code ให้ตรงกับผลการทำงาน Client จะรู้ทันทีว่าต้องทำอะไรต่อ
  • รับข้อมูลจาก Client ได้ 3 ทาง คือ Query, Path และ Body
  • ตรวจข้อมูลก่อนบันทึก ป้องกันข้อมูลผิดเข้าระบบยืมคืน
  • เข้าใจว่าทำไมระบบจริงต้องมีฐานข้อมูล

ก่อนเริ่ม

JOB.01 ต้องทำงานได้ครบ 4 Endpoint และ push ขึ้น GitHub แล้ว ถ้ายังไม่ครบ ให้กลับไปทำ Week 1 ก่อน สัปดาห์นี้ต่อยอดใน Repository เดิม

แนวคิด

1. Request และ Status Code

Request ทุกครั้งมี Method บอกว่าจะทำอะไร และ URL บอกว่าทำกับอะไร บางครั้งมี Body คือข้อมูลที่ส่งไปด้วย ส่วน Response มี Status Code บอกผล และ Body คือข้อมูลที่ตอบกลับ

Methodใช้ทำอะไรมี Body
GETขอดูข้อมูลไม่มี
POSTสร้างข้อมูลใหม่มี

Status Code ที่ใช้ในวิชานี้

เลข 3 หลัก ตัวแรกบอกกลุ่ม: 2 คือสำเร็จ, 4 คือฝั่ง Client ส่งมาผิด, 5 คือฝั่ง Server พัง

Statusความหมายใช้เมื่อตัวอย่าง
200OKสำเร็จและมีข้อมูลตอบกลับGET รายการอุปกรณ์
201Createdสร้างข้อมูลใหม่สำเร็จPOST เพิ่มอุปกรณ์
400Bad Requestข้อมูลที่ส่งมาผิดรูปแบบหรือไม่ครบID เป็น abc, quantity ติดลบ
404Not Foundข้อมูลรูปแบบถูก แต่ไม่มีอยู่จริงค้นหา ID 9999
500Internal Server Errorโค้ดฝั่ง Server ทำงานผิดพลาดโค้ดพังระหว่างประมวลผล

ใน Express กำหนดด้วย res.status() ตามด้วย .json() ถ้าไม่กำหนด Express จะตอบ 200 ให้เอง

res.json(item);                                   // 200
res.status(201).json(newItem);                     // 201
res.status(404).json({ message: 'ไม่พบอุปกรณ์' });  // 404

เฉาก๊วยบอก

ทุกครั้งที่ตอบ error ให้มี message บอกเหตุผลด้วย คนที่เรียก API จะได้รู้ว่าต้องแก้อะไร แทนที่จะเห็นแค่ 400 แล้วงง

2. Query Parameter

Query Parameter คือข้อมูลที่ต่อท้าย URL หลังเครื่องหมาย ? เขียนเป็น ชื่อ=ค่า ถ้ามีหลายตัวคั่นด้วย & นิยมใช้กับการ กรอง ค้นหา และเรียงลำดับ

GET /api/equipment?category=computer
// ใน Express อ่านได้จาก req.query
// req.query = { category: 'computer' }

ค่าใน req.query เชื่อไม่ได้

ผู้ใช้พิมพ์อะไรต่อท้าย URL ก็ได้ เช่น ?category= (ว่าง) หรือ ?category=a&category=b ซึ่ง Express จะให้ค่าเป็น Array ['a', 'b'] ไม่ใช่ข้อความ ต้องตรวจก่อนนำไปใช้เสมอ

3. Path Parameter

Path Parameter คือค่าที่เป็นส่วนหนึ่งของพาธ ใน Route ประกาศด้วย :ชื่อ นิยมใช้ ระบุข้อมูลชิ้นเดียว

GET /api/equipment/101
// Route: '/api/equipment/:id'
// req.params = { id: '101' }  ← เป็นข้อความเสมอ
Query ParameterPath Parameter
หน้าตา/api/equipment?category=computer/api/equipment/101
อ่านจากreq.query.categoryreq.params.id
ใช้เมื่อกรองหรือค้นหา ผลอาจมีหลายรายการหรือไม่มีเลยระบุรายการเดียวที่รู้ตัวตนแน่นอน
ไม่พบข้อมูลตอบ 200 พร้อม []ตอบ 404

  • ต้องการดูอุปกรณ์ ID 101 ควรใช้แบบใด

  • ?category=furniture แล้วไม่มีอุปกรณ์ประเภทนี้เลย ควรตอบอะไร

ลงมือเขียน

4. Workshop 01 กรองตามประเภท

แก้ Route GET /api/equipment เดิม ถ้าไม่ส่ง category ให้ตอบทั้งหมดเหมือนเดิม ถ้าส่งมาให้ตรวจก่อนแล้วค่อยกรอง

เพิ่มฟังก์ชันช่วยตรวจข้อความไว้ใต้ Array equipment

server.js
function isNonEmptyString(value) {
  return typeof value === 'string' && value.trim() !== '';
}
server.js (แทน Route GET /api/equipment เดิม)
app.get('/api/equipment', (req, res) => {
  const { category } = req.query;

  if (category === undefined) {
    return res.json(equipment);
  }

  if (!isNonEmptyString(category)) {
    return res.status(400).json({ message: 'category ต้องเป็นข้อความที่ไม่ว่าง' });
  }

  const keyword = category.trim().toLowerCase();
  const result = equipment.filter(item => item.category.toLowerCase() === keyword);
  res.json(result);
});

return หน้า res.json() ทำให้ฟังก์ชันจบตรงนั้น ถ้าลืมใส่ โค้ดจะทำงานต่อแล้วพยายามตอบซ้ำ Express จะแจ้ง error ว่าส่ง Response ไปแล้ว

toLowerCase() ทำให้ Computer กับ computer ค้นเจอเหมือนกัน และ trim() ตัดช่องว่างหัวท้ายที่เผลอพิมพ์มา

5. Workshop 02 ค้นหาด้วย ID

ID ที่ถูกต้องในระบบนี้คือจำนวนเต็มบวก ถ้ารูปแบบผิดตอบ 400 ถ้ารูปแบบถูกแต่ไม่มีตอบ 404 เพิ่มฟังก์ชันแปลง ID ไว้ใต้ isNonEmptyString

server.js
function parseId(value) {
  if (!/^\d+$/.test(value)) return null;   // ต้องเป็นตัวเลขล้วน
  const id = Number(value);
  return Number.isSafeInteger(id) && id > 0 ? id : null;
}
ทำไมไม่ใช้ Number(req.params.id) ตรง ๆ

Number() ยอมรับค่าแปลก ๆ หลายแบบ เช่น Number('1e2') ได้ 100 และ Number('0x65') ได้ 101 ส่วน /^\d+$/ ยอมเฉพาะตัวเลข 0 ถึง 9 ล้วน แล้ว Number.isSafeInteger() กันตัวเลขยาวเกินที่ JavaScript เก็บได้แม่นยำ

เพิ่ม Route ค้นหาด้วย ID ต่อจาก Route /api/equipment/count

server.js
app.get('/api/equipment/:id', (req, res) => {
  const id = parseId(req.params.id);

  if (id === null) {
    return res.status(400).json({ message: 'ID ต้องเป็นจำนวนเต็มบวก' });
  }

  const item = equipment.find(e => e.id === id);

  if (!item) {
    return res.status(404).json({ message: `ไม่พบอุปกรณ์ ID ${id}` });
  }

  res.json(item);
});

/count ต้องอยู่ก่อน /:id

Express ตรวจ Route จากบนลงล่าง ใช้ตัวแรกที่ตรง ถ้า /api/equipment/:id อยู่ก่อน คำว่า count จะถูกมองเป็น ID แล้วได้ 400 เพราะไม่ใช่ตัวเลข Route ที่พาธตายตัวต้องอยู่ก่อน Route ที่มี : เสมอ

6. Workshop 03 เพิ่มอุปกรณ์ด้วย POST

เปิดให้ Express อ่าน JSON

POST ส่งข้อมูลมาใน Body ไม่ได้อยู่ใน URL Express อ่าน Body เองไม่เป็น ต้องเปิด express.json() ไว้ต่อจากบรรทัดสร้าง app แล้วจะอ่านได้จาก req.body

server.js
const app = express();
const PORT = 3000;

app.use(express.json());

ตัวนับ ID

เพิ่มตัวแปรนี้ใต้ Array equipment ใช้ออกเลข ID ให้อุปกรณ์ใหม่

server.js
let nextId = 104;

nextId++ ให้ค่าปัจจุบันไปใช้ก่อน แล้วค่อยบวก 1 รอไว้ ชิ้นแรกได้ 104 ชิ้นต่อไปได้ 105

ทำไมไม่ใช้ equipment.length + 1

ตอนนี้มี 3 รายการ length + 1 ได้ 4 ซึ่งไม่ต่อจาก 103 และสัปดาห์หน้าเมื่อลบอุปกรณ์ได้ length จะลดลง ID ใหม่จะซ้ำกับของที่มีอยู่ ตัวนับที่เพิ่มขึ้นอย่างเดียวจึงปลอดภัยกว่า

ตรวจข้อมูลก่อนบันทึก

เงื่อนไขของอุปกรณ์ใหม่: name และ category เป็นข้อความที่ไม่ว่างหลัง trim() ส่วน quantity เป็นจำนวนเต็มตั้งแต่ 0 ขึ้นไป เพิ่มฟังก์ชันตรวจอีก 2 ตัว

server.js
function isValidQuantity(value) {
  return Number.isSafeInteger(value) && value >= 0;
}

function isPlainObject(value) {
  return value !== null && typeof value === 'object' && !Array.isArray(value);
}

Number.isSafeInteger("3") ได้ false เพราะ "3" เป็นข้อความ ไม่ใช่ตัวเลข ใน JSON ต้องเขียน "quantity": 3 ไม่มีเครื่องหมายคำพูด

server.js
app.post('/api/equipment', (req, res) => {
  const body = req.body;

  if (!isPlainObject(body)) {
    return res.status(400).json({ message: 'Body ต้องเป็น JSON Object' });
  }

  const { name, category, quantity } = body;

  if (!isNonEmptyString(name)) {
    return res.status(400).json({ message: 'name ต้องเป็นข้อความที่ไม่ว่าง' });
  }
  if (!isNonEmptyString(category)) {
    return res.status(400).json({ message: 'category ต้องเป็นข้อความที่ไม่ว่าง' });
  }
  if (!isValidQuantity(quantity)) {
    return res.status(400).json({ message: 'quantity ต้องเป็นจำนวนเต็มตั้งแต่ 0 ขึ้นไป' });
  }

  const newItem = {
    id: nextId++,
    name: name.trim(),
    category: category.trim(),
    quantity
  };

  equipment.push(newItem);
  res.status(201).json(newItem);
});

isPlainObject ตรวจก่อนเพราะถ้าไม่ได้ส่ง Body มาเลย Express 5 ให้ req.body เป็น undefined ถ้าเอาไปแยกค่าด้วย const { name } = req.body ทันที Server จะพังเป็น 500

จัดการ JSON รูปแบบผิด

ถ้า Client ส่ง JSON ที่เขียนผิด เช่น ลืมปิดวงเล็บ express.json() จะโยน error ออกมา ให้เพิ่ม Error handler ไว้ หลัง Route ทั้งหมด ก่อน app.listen()

server.js
app.use((err, req, res, next) => {
  if (err.type === 'entity.parse.failed') {
    return res.status(400).json({ message: 'รูปแบบ JSON ไม่ถูกต้อง' });
  }
  console.error(err);
  res.status(500).json({ message: 'เกิดข้อผิดพลาดที่ Server' });
});

Error handler ต้องมีพารามิเตอร์ครบ 4 ตัว Express จึงรู้ว่าเป็นตัวจัดการ error แม้จะไม่ได้ใช้ next ก็ตาม

ดู server.js ฉบับเต็มของ Week 2
server.js
import express from 'express';

const app = express();
const PORT = 3000;

app.use(express.json());

const equipment = [
  { id: 101, name: 'Notebook', category: 'computer', quantity: 5 },
  { id: 102, name: 'Projector', category: 'display', quantity: 2 },
  { id: 103, name: 'PC', category: 'computer', quantity: 10 }
];

let nextId = 104;

function isNonEmptyString(value) {
  return typeof value === 'string' && value.trim() !== '';
}

function parseId(value) {
  if (!/^\d+$/.test(value)) return null;
  const id = Number(value);
  return Number.isSafeInteger(id) && id > 0 ? id : null;
}

function isValidQuantity(value) {
  return Number.isSafeInteger(value) && value >= 0;
}

function isPlainObject(value) {
  return value !== null && typeof value === 'object' && !Array.isArray(value);
}

app.get('/', (req, res) => {
  res.send('Hello, Backend!');
});

app.get('/api/health', (req, res) => {
  res.json({ status: 'ok' });
});

app.get('/api/equipment', (req, res) => {
  const { category } = req.query;

  if (category === undefined) {
    return res.json(equipment);
  }

  if (!isNonEmptyString(category)) {
    return res.status(400).json({ message: 'category ต้องเป็นข้อความที่ไม่ว่าง' });
  }

  const keyword = category.trim().toLowerCase();
  const result = equipment.filter(item => item.category.toLowerCase() === keyword);
  res.json(result);
});

app.get('/api/equipment/count', (req, res) => {
  res.json({ total: equipment.length });
});

app.get('/api/equipment/:id', (req, res) => {
  const id = parseId(req.params.id);

  if (id === null) {
    return res.status(400).json({ message: 'ID ต้องเป็นจำนวนเต็มบวก' });
  }

  const item = equipment.find(e => e.id === id);

  if (!item) {
    return res.status(404).json({ message: `ไม่พบอุปกรณ์ ID ${id}` });
  }

  res.json(item);
});

app.post('/api/equipment', (req, res) => {
  const body = req.body;

  if (!isPlainObject(body)) {
    return res.status(400).json({ message: 'Body ต้องเป็น JSON Object' });
  }

  const { name, category, quantity } = body;

  if (!isNonEmptyString(name)) {
    return res.status(400).json({ message: 'name ต้องเป็นข้อความที่ไม่ว่าง' });
  }
  if (!isNonEmptyString(category)) {
    return res.status(400).json({ message: 'category ต้องเป็นข้อความที่ไม่ว่าง' });
  }
  if (!isValidQuantity(quantity)) {
    return res.status(400).json({ message: 'quantity ต้องเป็นจำนวนเต็มตั้งแต่ 0 ขึ้นไป' });
  }

  const newItem = {
    id: nextId++,
    name: name.trim(),
    category: category.trim(),
    quantity
  };

  equipment.push(newItem);
  res.status(201).json(newItem);
});

app.use((err, req, res, next) => {
  if (err.type === 'entity.parse.failed') {
    return res.status(400).json({ message: 'รูปแบบ JSON ไม่ถูกต้อง' });
  }
  console.error(err);
  res.status(500).json({ message: 'เกิดข้อผิดพลาดที่ Server' });
});

app.listen(PORT, () => {
  console.log(`Server running at http://localhost:${PORT}`);
});

  • ID ใหม่ใช้ตัวนับ ไม่ใช้ equipment.length + 1
  • Route /api/equipment/count อยู่ก่อน /api/equipment/:id
  • ตรวจ Query ก่อนนำไปใช้
  • มี Error handler สำหรับ JSON รูปแบบผิด

แก้ปัญหาที่พบบ่อย

POST แล้วได้ 400 Body ต้องเป็น JSON Object ทั้งที่ใส่ข้อมูลแล้ว

ใน Thunder Client ต้องใส่ข้อมูลที่แท็บ Body และเลือก JSON ถ้าใส่ใน Form หรือ Text Server จะไม่ได้รับเป็น JSON ตรวจด้วยว่ามี app.use(express.json()) อยู่ก่อน Route ทั้งหมด

/api/equipment/count ได้ 400 ID ต้องเป็นจำนวนเต็มบวก

Route /:id อยู่ก่อน /count ให้ย้าย /count ขึ้นไปไว้ก่อน

JSON ผิดรูปแบบแล้วได้หน้า HTML ยาว ๆ หรือ 500

Error handler อยู่ผิดตำแหน่ง ต้องอยู่หลัง Route ทั้งหมด และต้องมีพารามิเตอร์ครบ 4 ตัว (err, req, res, next)

Cannot set headers after they are sent to the client

ตอบ Response มากกว่า 1 ครั้งใน Route เดียว มักเกิดจากลืม return หน้า res.status(400).json(...) โค้ดจึงทำงานต่อไปถึงบรรทัด res.json() ด้านล่าง

id ของอุปกรณ์ใหม่ไม่ต่อจากเดิม หรือซ้ำกัน

ตรวจว่าใช้ id: nextId++ และประกาศ nextId ด้วย let ไม่ใช่ const เพราะค่าต้องเปลี่ยนได้

กรองด้วย category แล้วได้ [] ทั้งที่มีข้อมูล

ดูตัวสะกดใน URL กับในข้อมูล เช่น computer กับ computers และตรวจว่าเปรียบเทียบหลัง toLowerCase() ทั้งสองฝั่ง

Exit Ticket

ตอบด้วยคำพูดของตัวเองสั้น ๆ แล้วกดสรุปเพื่อคัดลอกส่งครู

1. เลือก Query หรือ Path เมื่อต้องการค้นหาอุปกรณ์ ID 101 พร้อมอธิบายเหตุผล

แนวคำตอบ: ใช้ Path คือ /api/equipment/101 เพราะ ID ระบุอุปกรณ์ชิ้นเดียวที่รู้ตัวตนแน่นอน ส่วน Query เหมาะกับการกรองหรือค้นหาที่ผลอาจมีหลายรายการ

2. 201, 400 และ 404 ใช้ต่างกันอย่างไร?

แนวคำตอบ: 201 สร้างข้อมูลใหม่สำเร็จ, 400 ข้อมูลที่ส่งมาผิดรูปแบบหรือไม่ครบ, 404 รูปแบบถูกแต่หาข้อมูลนั้นไม่พบ

3. ทำไม quantity: "3" จึงไม่ผ่าน และควรแก้ข้อมูลที่ส่งอย่างไร?

แนวคำตอบ: "3" มีเครื่องหมายคำพูดจึงเป็นข้อความ Number.isSafeInteger จึงได้ false ต้องส่งเป็นตัวเลข "quantity": 3

4. ถ้าส่ง POST สำเร็จแล้วรีสตาร์ต Server ข้อมูลใหม่หายเพราะอะไร?

แนวคำตอบ: ข้อมูลเก็บใน Array ซึ่งอยู่ในหน่วยความจำของโปรแกรม เมื่อ Server หยุดหน่วยความจำก็ถูกล้าง ต้องใช้ฐานข้อมูลจึงจะเก็บได้ถาวร
